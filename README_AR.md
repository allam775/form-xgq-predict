# FORM / XGQ — موقع توقعات مستقل يعمل أونلاين

هذه نسخة **مستقلة تمامًا عن واجهة XGQ Analyzer**. لا تحتاج تشغيل Flask أو Vite الأصلي. التصميم HTML/CSS/JavaScript مستقل، وتخزين ونشر البيانات على Cloudflare Worker + D1.

**مهم:** لا تُعرض احتمالات من النموذج القديم القائم على النتائج. النموذج الجديد لا يقبل إلا تسديدات حقيقية تحتوي xG لكل تسديدة، ويطبّق `XGQ = sum(shot_xg²)/shots`. يتم استخدام النتائج المسجلة للضبط الإحصائي لمعدلات الأهداف فقط؛ مفتاح الإشارة المتغير هو XGQ الفعلي. ليس نموذجًا تعلّم عميقًا، وليس معدلًا مثبَتًا للدقة المستقبلية.

## ما يعمل وما لم يُفعّل بعد

- ✅ واجهة جديدة بالكامل ومستقلة، بحث، فلاتر **Today / 7 days / Upcoming**، شارة XGQ، نموذج بطاقات وشعارات جاهز لوصلة صور مرخصة.
- ✅ محرك Python حقيقي، بيانات StatsBomb بشروط الإسناد، إمكانية إدخال صادرات shot-xG من XGQ القديم، ورفض البيانات المجمّعة/القديمة، وقياس تاريخي مشروط.
- ✅ قراءة الجدول القادم من OpenFootball. المصدر أفضل جهد ولا يضمن المواعيد/النتائج الحية.
- ✅ Cloudflare Worker API وD1 schema، أداة تحويل النتائج إلى SQL آمن، GitHub Actions للتحديث والنشر المجدول.
- ⚠️ لا توجد شعارات رسمية مضمّنة دون إثبات حق استخدامها. `config/club_logos.json` يستوعب شعار كل فريق برابط HTTPS وترخيص صالح؛ خلاف ذلك يعرض شكلًا احتياطيًا بحروف الفريق.
- ⚠️ StatsBomb Open Data جزئي وتاريخي في مسابقات محددة. غالبًا **لن ينتج توقعات مؤهلة لمباريات أكتوبر 2026** حتى نصل مصدر تسديدات حديثًا وقانونيًا. لن تُخترع أرقام لإخفاء هذه الفجوة.
- ⚠️ نشر D1 وCloudflare يحتاج دخول المستخدم لحسابه وإنشاء الموارد مرة واحدة، وإضافة أسرار GitHub. لم تنفذ تلك الخطوات على حساب المستخدم بعد.

## أسرع اختبار محلي باستخدام CMD

افتح CMD داخل المجلد الجديد (وليس مجلد XGQ_Phase5 القديم):

```cmd
py -3.12 -m unittest discover -s tests -v
node --check site\app.js
node --check worker\index.js
```

اختبار صيغة بيانات محفوظة (لو عندك تصدير XGQ حقيقي، مش ملف المثال):

```cmd
py -3.12 -m engine.collect --offline --verified-feed data\verified_matches.json
py -3.12 -m engine.validate
py -3.12 -m engine.sql_export
```

تنبيه: في نمط `--offline` لا يجلب المصدر مواعيد من الإنترنت. أضف `data/fixtures.json` لاختبار التغطية. ولا تستخدم `config/example_verified_shot_feed.json` لتوليد أرقام عامة: المثال لتوضيح الصيغة فقط.

## إتاحة الموقع للجمهور: إعداد Cloudflare مرة واحدة

1. أنشئ حساب Cloudflare مجانيًا، وافتح Cloudflare Dashboard → Workers & Pages → D1 → Create database، باسم **xgq-predictions**. انسخ **Database ID** و**Account ID**.
2. ضع المشروع في **مستودع GitHub مستقل** (غير مستودع XGQ Analyzer)، ويُفضّل جعله Public إذا أردت GitHub Actions دون دقائق مدفوعة.
3. من GitHub → Settings → Secrets and variables → Actions → New repository secret، أضف `CLOUDFLARE_API_TOKEN` (توكن محدود بصلاحية نشر Workers وD1 فقط)، و`CLOUDFLARE_ACCOUNT_ID`، و`CF_D1_DATABASE_ID`.
4. لو لديك خدمة XGQ تخصك تعيد JSON صحيحًا بمصفوفات التسديدات الحديثة، أضف سرًا اختياريًا `XGQ_SHOT_FEED_URL` يحتوي رابط **HTTPS** عام مُصرّح بإعادة استخدام بياناته. يجب أن يعيد قائمة مطابقة للصيغة أدناه. لا تستعمل رابط API طرف ثالث محمي أو غير مصرح به.
5. شغّل Workflow من GitHub → Actions → **Update independent XGQ predictions online** → Run workflow. يبدأ تنزيل البيانات والتحقق ثم تحديث D1 ثم نشر Worker والواجهة. بعد نجاحه يظهر عنوان `workers.dev` في سجلات الخطوة `Publish independent site and online API`.
6. يعمل الجدول يوميًا 08:40 UTC في حدود الخدمة المجانية، مع إمكانية التأخير. جهازك ليس مطلوبًا بعد النشر.

Cloudflare D1 له حدود مجانية (قراءة 5M صف/يوم، كتابة 100K صف/يوم، 5GB إجمالي)، والتجاوز يمنع الاستعلامات حتى إعادة الضبط. احرص على مراقبة الاستهلاك. إذا لم يكن هناك سجل حديث من XGQ للفريقين، الموقع سيعرض أن النموذج ليس لديه بيانات كافية بدل إنشاء احتمالات وهمية.

## شكل ملف تصدير XGQ الذي نحتاجه

```json
[
  {
    "league": "en.1", "date": "2026-10-01",
    "home_team": "Arsenal", "away_team": "Chelsea",
    "home_goals": 2, "away_goals": 1,
    "home_shots_xg": [0.03, 0.12, 0.19, 0.38],
    "away_shots_xg": [0.02, 0.08, 0.24],
    "source": "authorized-own-XGQ-feed", "source_match_id": "real-source-id"
  }
]
```

هذه مجرد **وثيقة بنيوية توضيحية لا تعكس نتيجة مباراة حقيقية**. التحديث سيقرأ مباريات أخرى كثيرة بهذه البنية. يلزم على الأقل 5 مباريات XGQ سابقة لكل فريق، و40 مباراة لقاعدة الدوري، وتاريخ تسديدات غير قديم (120 يومًا كحد افتراضي). مواعيد اليوم قد لا تكون موثوقة في OpenFootball، لذا يظهر تحذير المصدر ولا تُقدّم على أنها مؤكدة قبل البداية.

## إضافة الشعارات ذات الترخيص المسموح

ضع في `config/club_logos.json` بيانات الفريق بالاسم الموحّد (أحرف إنجليزية صغيرة دون FC في آخر الاسم)، مثل:

```json
{
  "example team": {
    "url": "https://example.com/licensed-club-logo.svg",
    "permission_verified": true,
    "license_note": "source / license / attribution"
  }
}
```

عند اتصال مصدر XGQ حديث يمكن إكمال الشعارات الفعلية من بيانات الأندية بشرط أن يسمح مصدر الصور بإعادة العرض. لا يوجد سبب لربط الموقع الجديد بواجهة XGQ القديمة.

## هيكل المشروع

`engine/` استخراج XGQ والتوقع والتقييم؛ `worker/index.js` API D1؛ `site/` الواجهة؛ `migrations/` تعريف قاعدة البيانات؛ `config/` شعارات وإرشادات المصدر؛ `.github/workflows` البايبلاين التلقائي.

**تراخيص البيانات:** StatsBomb Open Data يستخدم شروطًا مذكورة في README وLICENSE.pdf، ويشترط ذكر StatsBomb واستخدام شعار المصدر عند نشر التحليلات. راجع شروط الاستخدام قبل النشر التجاري. OpenFootball مصدر جداول، وقد يتأخر تحديثه. استخدام شعارات الأندية يخضع لترخيصها/علاماتها التجارية.

## نقاط تقنية مهمة

- **السلامة أثناء التحديث:** يكتب البايبلاين كل إصدار في صفوف D1 مرتبطة برقم إصدار، ولا يغيّر مؤشر `published_generation` إلا بأخر عبارة SQL. هذا يحافظ على النسخة المعروضة إذا تعطل استيراد الإصدار الجديد قبل إتمامه. لا يُستخدم `BEGIN TRANSACTION` لأنه غير مدعوم في D1 عبر ملف الاستيراد.
- **تحديث يوم المباراة:** لأن المصدر لا يقدم تأكيدًا لحظة البداية والمنطقة الزمنية لكل مباراة، تُميّز المباراة بتاريخ اليوم بأنها غير مؤكدة الحالة. استخدم مصدر kickoff موثوقًا قبل اعتبار جميع التوقعات مسبقة للمباراة.
- **التوافق:** مشروعك المحلي القديم XGQ_Phase5 لا يتغير. الموقع الجديد لا يحتاج استخراج SQLite القديمة ذات النتائج فقط؛ يحتاج مصدرًا حديثًا يحتوي التسديدات الفردية.
- **ملاحظة الإسناد:** عند استخدام بيانات StatsBomb علنًا، يشترط المصدر أيضًا إظهار شعار StatsBomb من حزمة الوسائط المعتمدة. ينبغي إضافته قبل النشر العام؛ الرابط النصي وحده ليس بديلًا مضمونًا عن الشرط المذكور.
- **نطاق الاختبارات:** اجتياز اختبارات Python وJS وملف SQL محليًا لا يعني أن GitHub Actions أو Cloudflare D1 أو جمع الأحداث الحية قد عملت بالفعل؛ يجب التحقق منها في الحساب بعد الربط.
